# V4.0 Agentic Business Workflows

V4.0 turns domain Agents into business-loop executors: decompose -> read -> analyze -> propose -> approval -> write -> verify -> report.

## Safety boundary
Write/control actions are represented by approval-required steps. Production integrations must enforce tenant/RBAC/policy/audit again at the connector boundary.

## Workflow model
DAG steps support dependencies, resumable state, approval pauses and domain handler adapters. The in-memory engine is a development baseline; production should persist state in PostgreSQL/Redis and use the existing worker/checkpoint infrastructure.

## Example
Project Agent: schedule read -> variance analysis -> proposed Gantt update -> approval -> write to project system -> verification -> report.
BIM Agent: inspect model -> detect issue -> generate issue list -> approval -> create issue -> verify.
Water Agent: telemetry -> KPI -> advisory -> approval -> control adapter -> verification.
IoT Agent: telemetry -> anomaly -> root cause -> work order -> notification -> closure.
